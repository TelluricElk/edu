Этот документ — самодостаточная передача контекста. Новый чат **не имеет
доступа** к файлам, которые создавались в песочнице предыдущего разговора —

## Что это за проект

**EduAppML** — образовательное Android-приложение об машинном обучении.
Kotlin + Jetpack Compose. Владелец и разработчик — Samir (в переписке — Роман,
судя по контактам в приложении: rnk@romannk.ru).

Репозиторий: **https://github.com/TelluricElk/edu** (публичный — можно
открывать файлы напрямую через `web_fetch`, только не `/tree/` и не
`/commits/` — они закрыты от ботов robots.txt; `/blob/` и `/raw/` работают).

Устройство приложения: два раздела с картой пузырей —
**классические алгоритмы ML** (`MenuScreen`) и **нейросетевые архитектуры**
(`ThirdScreen`). Клик по пузырю темы раскладывает его на 6 спутниковых
пузырей: Теория → Задача → Мат. основа → Код → Интерактив → Решение.
Плюс встроенный чат-ассистент «Edu.AI» (на GigaChat через Supabase Edge
Function).

## Текущее состояние на момент написания

**Контент всех 19 тем полностью реализован**, для каждой — все 6 спутниковых
экранов с настоящими, честно посчитанными алгоритмами (не имитация):

- Классика (9): `lr`, `logr`, `knn`, `nb`, `svm`, `dt`, `rf`, `gb`, `km`

Из них `tr` (Трансформер) и `dm` (Диффузионная модель) — единственные два,
где сознательно **не** имитируется обучение (честно объяснено пользователю
в самом контенте почему), но математика вокруг них (self-attention,
positional encoding, score-функция для смеси гауссиан) посчитана точно.

**Дополнительно за последние несколько сессий сделано:**

## Как работать над этим проектом — важные правила

1. **В архив/патч попадают только реально изменённые в конкретном ответе
   файлы**, не весь проект. Это явная договорённость с пользователем —
   один раз уже была ситуация, когда старая локальная копия файла попала в
   архив "заодно" и создала риск регресса рабочей функциональности.

2. **`project_knowledge_search` может отражать устаревший снэпшот**, а не
   актуальный репозиторий. Несколько раз важные файлы (`AppRoot.kt`,
   `SplashForeground.kt`) в снэпшоте оказывались старее, чем то, что реально
   в репозитории. При любом сомнении в актуальности критичного файла —
   свериться напрямую через `web_fetch` по ссылке на GitHub (см. выше про
   `/blob/`).

3. **Перед переносом любого алгоритма с обучением в Kotlin — сначала
   симуляция в Python.** Численно проверить градиент (для ручного backprop),
   прогнать по сетке гиперпараметров/seed, только потом фиксировать диапазоны
   слайдеров и дефолты. Так было найдено и исправлено несколько реальных
   багов (LR — ненормализованные признаки, GNN — перепутанный `dL/dp` vs
   `dL/dz`, RNN — настоящая проблема затухающего градиента, которую не стали
   "чинить", а сделали частью урока).

4. **Если файл реконструируется по фрагментам поиска** (а не редактируется
   точечно через `str_replace`) — не гадать неизвестные куски. Если один и
   тот же фрагмент систематически обрывается в одном месте при разных
   запросах — это, скорее всего, реальная граница содержимого.

5. **Стиль контента** — весь текстовый материал на русском, Python как
   педагогически основной язык в разделе «Код», Kotlin — как эталонная
   реализация. Каждая тема: сцена/метафора, привязанная к тому же датасету,
   что в интерактиве → история → применение → как работает → термины →
   философия/цена → резюме.

## Идеи на будущее (обсуждались, но не реализованы)

Пользователь просил их запомнить для следующих сессий:

**Новый контент:** VAE (логичное продолжение AE), PCA/снижение размерности
(сосед SOM и AE), policy gradient RL (сейчас только табличный Q-learning).

**Кросс-тематические фичи:** режим сравнения алгоритмов на одних данных,
опросник "какой алгоритм выбрать", сквозной поиск по терминам, итоговый
экзамен по всем 19 темам.

**Полировка:** загрузка пользователем своих данных вместо игрушечного
примера, онбординг при первом входе, локализация на английский.

**Инфраструктура:** юнит-тесты на каждый `*Lab.kt` (диапазоны параметров уже
откалиброваны — стоит закрепить тестами), автоматизация LaTeX-проверки в
CI/pre-commit, реальный профайлинг производительности на слабом устройстве
(особенно SVM/CNN/GNN).

**Чат:** контекстные подсказки ("объяснить эту формулу" со страницы
Математики), чат видит, на какой теме находится пользователь.
