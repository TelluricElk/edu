# Правила и ограничения работы

## Режим работы (с 15.09.2026)

У ассистента есть **прямой доступ к папке проекта** на машине владельца:
`C:\Users\sasaa\yurovskiy\kozlov\EduAppML v.19`.

Согласованный уровень самостоятельности: **правит файлы сам, отчитывается после**.

Что это меняет по сравнению со старым порядком:

- Зип-архивы с изменёнными файлами больше не нужны — правки пишутся прямо в папку.
- «Свериться с актуальным состоянием» теперь означает «прочитать файл из папки»,
  а не сверяться с GitHub-снэпшотом. Локальная рабочая копия — источник правды.
  (GitHub остаётся полезен, только если нужно понять, что уже закоммичено.)
- Правило «готовить полные файлы для замены» отменяется в пользу **точечных правок**.
  Целиком файл переписывается только когда это действительно оправдано, и тогда
  список публичных функций сверяется до/после (прецеденты в `AGENTS.md`).

## Чего ассистент физически не может на этой машине

Нет shell-доступа к компьютеру владельца. Значит **за владельцем остаётся**:

- `./gradlew assembleDebug` и любая сборка;
- git (`add`/`commit`/`push`), просмотр диффов;
- запуск приложения, `adb`, проверка на устройстве.

Ассистент может: читать и писать файлы в папке, запускать Python/Node **у себя**
в облаке (симуляции алгоритмов, проверка LaTeX, статический разбор `.kt`).

Сборку в облаке прогнать нельзя (нет Android SDK, закрыт `dl.google.com`).
Проверка правок — статическая, финальное слово за сборкой на машине владельца.

## Обязательные проверки перед тем, как сказать «готово»

1. **LaTeX** — по каждому новому/изменённому `math.ru.md` прогнать скрипт из
   `DEVELOPMENT_NOTES.md` §3 (баланс `$`, кириллица внутри формул, `\mathbb`).
2. **Синтаксис Kotlin** — tree-sitter-kotlin по изменённым `.kt`.
   Известная ложная тревога: `ui/rnn/RnnLab.kt`, `ui/rnn/RnnLabMilitary.kt`
   (переменная `by` — мягкое ключевое слово, компилятор принимает, парсер нет).
3. **Симметрия гражданской и военной версий** — см. ниже.
4. **Новый алгоритм с обучением** — сначала Python-симуляция с численной проверкой
   градиента и прогоном по сетке гиперпараметров, только потом Kotlin
   (`DEVELOPMENT_NOTES.md` §4).

## Перекрёстные зависимости между темами — ОБЯЗАТЕЛЬНАЯ ПРОВЕРКА

Темы не изолированы были. На 16.09.2026 перекрёстных зависимостей между
темами **не осталось ни одной** — обе расцеплены при переводе на ИБ:

- **`gb` зависел от `lr`.** `GbLab` брал `LrLab.trainSet`/`testSet` и тип
  `PricePoint`, `GbInteractive` — `LrLab.AREA_MIN`/`AREA_MAX`/`trainSet`.
  Расцеплено 15.09.2026: у `gb` собственный датасет (`GbPoint`, та же
  генерация с теми же сидами, поведение экрана не изменилось).
- **`rf` зависел от `dt`.** `RfLab` импортировал `CreditPoint`,
  `DtCriterion`, `DtLab`, `DtNode`; `RfInteractive` — `CreditPoint` и
  `DtLab`. Расцеплено 16.09.2026 вместе с переводом обеих тем: у `rf` теперь
  собственные `PeSample`, `RfCriterion`, `RfTreeNode`, `RfForest` и
  собственный код дерева.

Военные файлы этой развязки не касаются: `RfLabMilitary` работает через
`DtLabMilitary`/`CandidatePoint`/`DtNodeMilitary` и берёт из `dt` ровно один
тип — `DtCriterion`. Поэтому `DtCriterion` в новом `DtLab.kt` сохранён с
прежними членами `GINI` и `ENTROPY`; добавлять в него значения нельзя —
исчерпывающие `when` в военных файлах упадут.

Кроме них перекрёстных зависимостей нет — проверено по всем 38 `*Lab*.kt`
и всем 38 `*Interactive*.kt`.

**Правило перед переписыванием любого `*Lab.kt`:** сначала прогнать по всему
дереву `java/` поиск имени объекта и всех его публичных типов
(`grep -rn "XxxLab\.\|<ИмяТипа>" --include="*.kt"`). Если найдётся файл вне
папки темы — либо конвертировать обе темы вместе, либо сначала расцепить.

Цена пропуска этой проверки уже известна: переписанный `LrLab.kt` уронил
сборку `gb`, и владелец потерял на этом рабочий день.

Отдельно: `InteractiveScreen.kt` и `ResultScreen.kt` импортируют `KnnLab`,
`KnnMetric`, `KnnWeighting` и содержат СТАРЫЕ приватные `KnnInteractive`,
`KnnCanvas`, `SegmentedRow`, `KnnResult`, `knnQuiz` прямо в теле файлов.
При конвертации `knn` публичный `com.eduappml.ui.knn.KnnInteractive`
столкнётся с приватной функцией того же имени — приватные блоки и лишние
импорты удаляются в том же коммите.

## Что умеет и чего не умеет рендерер ассетов

`MarkdownText.kt` собирает Markwon **ровно с одним плагином** —
`JLatexMathPlugin`. Больше ничего не подключено.

**Таблиц нет.** Табличного плагина в сборке Markwon не существует, поэтому
markdown-таблица выводится сырым текстом с палками и дефисами. Это реальная
ошибка, допущенная в первой версии `logr/task.ru.md` и замеченная владельцем
при сборке. Вместо таблицы — список: жирный заголовок пункта, следующей
строкой пояснение.

Чем пользоваться можно: `**жирный**`, `*курсив*`, маркированные и
нумерованные списки, `inline code`, блоки кода тройными кавычками, блочные
формулы `$$`. Заголовки `#`…`####` до Markwon вообще не доходят — их
вырезает `parseLessonSections` и рисует нативными Compose-элементами.

Горизонтальные разделители `---` тоже вырезаются на этапе парсинга: они
безвредны, но и невидимы, так что смысловой нагрузки на них вешать нельзя.

## Симметрия civilian / military — главная ловушка этого проекта

Приложение содержит два параллельных набора наполнения. Гражданский **временно
отключён** (`ВАЖНОЕ.txt`), но в репозитории остаётся.

Дублируются целыми слоями:

- ассеты: `assets/info/classic/{id}/` и `assets/info/military/classic/{id}/`;
- код: `XxxLab.kt` / `XxxLabMilitary.kt`, `XxxInteractive.kt` /
  `XxxInteractiveMilitary.kt`, `XxxResult.kt` / `XxxResultMilitary.kt`.

**Правило:** любая правка *механики* (сигнатуры, проброс `nodeId`, работа с
`QuizSection`, фоновый поток) вносится в **оба** варианта. Правка *текста сценария*
— только в свой вариант. Если правится один файл из пары — в отчёте явно сказать,
почему второй не тронут.

## Границы

- Не менять `.git/`, `build/`, `.gradle/`, `.idea/`, `local.properties`.
- Не трогать рёбра графа (`defaultEdges()`, `thirdEdges()`) без явной просьбы —
  это порядок прохождения, а не картинка (`AGENTS.md`).
- Не откатывать подходы, которые владелец уже отверг, без нового запроса.
- Не менять file-scope больше, чем нужно для задачи.
- Перед правкой файла — прочитать его текущее содержимое из папки, не полагаться
  на то, что было в прошлой сессии.
- Каждая сессия с правками закрывается записью в `50-JOURNAL.md`.
